# White-label and licensing

A business can offer CallVault to its own users under its own name. We build the Android app with that business's name, icon and colours, put the download page on its domain, and keep running sign-in, private cloud backup, the admin dashboard and the updates behind it.

There are two ways to buy:

| | Licence | Buyout |
|---|---|---|
| Source code | Stays with us | The CallVault repository is handed over |
| Who else can buy CallVault | We may license it to others | Nobody; we stop selling it |
| Where it runs | On servers we run | Wherever the buyer decides |
| Updates | Six months included, then renewals | Six months included, then renewals |

The current prices are on the [white-label pricing page](https://callvault.aoneahsan.com/white-label/pricing), read live from our licensing service. CallVault ships one platform group, the mobile app, so there is no bundle to put together.

## What your users' phones still decide

A white-label build records the way CallVault does: through the microphone path an ordinary Android app may use. On many phones the other person is clear only on speaker, so your users should [test one real call](../getting-started/permissions.md) before relying on it. You publish the app to them, so the recording-consent law in your markets is yours to follow. This is general information, not legal advice.
